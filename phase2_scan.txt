## 3. Fetch Official AlphaFold Prediction Metadata
### Why metadata-driven download, not a hardcoded URL pattern
A common (and fragile) shortcut is to hardcode the file URL pattern, e.g. `AF-{accession}-F1-model_v4.pdb`. This assumes every entry is on model version `v4` and is a single, unfragmented model â€” neither is guaranteed. Instead we query AlphaFold DB's **official prediction metadata API** (`GET https://alphafold.ebi.ac.uk/api/prediction/{accession}`, documented alongside the AlphaFold DB release, Varadi et al. 2022), which returns the *exact, current* download URLs (`pdbUrl`, `paeDocUrl`) together with the `uniprotSequence` actually used to build that specific model, its UniProt coordinate range (`uniprotStart`, `uniprotEnd`), and the released model version (`latestVersion`). Driving the download from this metadata, rather than from an assumed filename, is the approach the AlphaFold DB documentation itself recommends for programmatic access.

### Why this matters for correctness, not just convenience
This metadata is also what lets us catch a subtle but important failure mode in Section 6: **UniProt's canonical sequence can be revised after an AlphaFold model was built.*
